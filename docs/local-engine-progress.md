# 本地音素引擎开发记录

日期：2026-11-12。依据：`pronunciation-engine-plan.md` v2。默认口音：英式 `en-gb`。本轮优先引擎，云端路线暂不接入。

## 已实现并运行

- 独立 Python 包与 CLI：`speakstar_engine/`。
- 音频解码、16 kHz 单声道、静音筛查和原录音时间偏移。
- eSpeak G2P，保存带重音的参考 IPA；不做重音评测。
- CTC Viterbi 对齐与 forward likelihood、GOP、受限替换和删除证据。
- 本地 ONNX 推理，模型校验和、英美口音/模型版本隔离的校准文件。
- logistic 校准训练、开发集阈值选择、按说话者划分、公开数据集特征提取、儿童子集独立报告。
- 未校准时分数为 null，全部 uncertain；有校准也不自动宣称 validated。
- 原有 Whisper 页面未接入新引擎，避免在准确率验收前给孩子未经验证的纠错。

## 实测（本机 Windows / Python 3.12 / CPU）

模型：`facebook/wav2vec2-xlsr-53-espeak-cv-ft`。导出记录及校验和在 `models/wav2vec2/metadata.json`。

| 项目 | fp32 | 实验性 int8 |
|---|---:|---:|
| ONNX 大小 | 1,263,937,322 字节 | 356,740,364 字节 |
| 模型加载 | 约 2.14 秒 | 约 0.85 秒 |
| 3 秒输入的纯推理 | 约 0.50 秒 | 约 0.25 秒 |
| 与 PyTorch 对比，3 秒输入最大 logit 绝对误差 | 0.00025 以下 | 约 0.80 |

导出数值检查使用随机波形，验证动态输入形状和计算一致性，**不验证发音准确度**。int8 的差异不能直接转换成发音分差，暂不作为默认模型。

另外使用本机 System.Speech 生成两份合成音频：

- `Three thin thumbs.` 对同名目标句：10 个参考音素完成对齐。
- `sink` 对目标 `think`：/θ/ 的替换证据支持 /s/（substitution LPR 约 +5.65）。

同一模型进程内，两次完整评测约 0.93 秒和 0.15 秒；不包含首次导入依赖、计算模型校验和及加载模型。样本长度不同，不能据此推断所有 3–5 秒录音的速度。

补充的英式 Hazel 合成语音长度为 4.79 秒（`Three thin thumbs. I see a red apple.`）：fp32 完整评测首次 1.39 秒，后两次 0.73、0.71 秒；其中纯模型推理约 0.58–0.63 秒。新建引擎时，包含权重校验和计算及加载约需 5.71 秒。记录在 `artifacts/smoke/benchmark.json`。这仍是单个合成样本，不代表儿童语音集。

验证结果：14 项引擎测试、2 项原应用测试通过；依赖一致性检查通过。校准/评测工具的测试使用明确标记的合成特征，仅验证流程。

生成的音频与 JSON 在 `artifacts/smoke/`，均为合成音频，没有儿童录音，也没有上传音频。这两个例子只说明流程可运行，不能推断儿童误报率。
